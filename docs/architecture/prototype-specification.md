# 第一版原型规格

## 1. 原型目标与范围结论

第一版原型只深入验证三件事：

1. **展示产品版图与角色差异：**展示 Workspace 主要界面，清楚区分 CFO 的决策工作面与财务执行人员的日常工作面。
2. **深入展示 CFO 决策闭环：**以一个重大 Decision Case 串联数据、分析、方案、CFO 审批、执行追踪和事后评价；其中数据、分析及方案必须详细可查。
3. **深入展示财务执行工作方式：**用待办和工作流整合 FP&A、Finance BP、财务经理及分析人员的日常工作，并展示同一执行任务未来如何在人工和 Agent 之间受控切换。

采用“**双角色、一深两浅**”策略：深入制作 CFO 与财务执行人员两个角色体验；财务执行人员由 **FP&A Analyst** 代表；深入制作一条决策闭环；其他两个重点场景及其余模块只制作入口、代表性界面和能力介绍。

原型不是生产系统，不连接真实企业系统。所有页面、图表、文件、通知、Agent 动作及回执持续显示“**模拟数据 / 非真实企业数据**”。

交付形态确认为可运行的桌面 Web 原型，而不是仅可点击的静态设计稿。它应具备真实路由、角色切换、连贯的本地模拟状态和关键操作反馈，但所有数据、Agent 运行、审批外部回执及企业系统交互均为模拟。

## 2. 原型深度分级

| 级别 | 定义 | 交互要求 |
| --- | --- | --- |
| L3 深入可演示 | 主持人可按角色完成连续任务，数据和状态前后连贯 | 可点击、可切换状态、支持关键正常/例外路径 |
| L2 代表性页面 | 展示该能力如何复用 Decision Case，但不完成整条流程 | 1–2 个典型页面或只读详情，允许有限下钻 |
| L1 入口与介绍 | 保留产品版图和未来能力位置 | 可导航；说明用途、输入输出、目标用户及“本原型未深入实现” |

不得用无响应的按钮假装功能已经实现。L1/L2 页面必须明确标注原型深度。

## 4. 双角色工作面

### 4.1 CFO Decision Cockpit

CFO 首屏回答五个问题：

1. 今天有哪些事项需要我决定？
2. 为什么现在需要决定，影响多大？
3. 推荐方案及主要替代方案是什么？
4. 已决定事项是否按计划执行？
5. 已完成事项是否实现了承诺价值？

#### 首屏组件

- **待我决策：**按影响、风险和截止时间排序；显示事项、触发、推荐方案、财务影响、置信度及所需动作。
- **重大经营变化：**只展示已触发或可能触发 Case 的变化，不制作通用 BI 大屏。
- **执行例外：**已批准但阻塞、超期或接近授权边界的行动。
- **价值评价：**预期价值、已验证实际价值、偏差和待验证金额。
- **范围过滤：**业务板块、基地、期间和 Case 类型。

CFO 点击待决策卡片后进入同一 Decision Case，但默认打开“决策摘要”，而不是落入数据准备任务。

### 4.2 Finance Workbench / My Work

财务执行人员首屏回答五个问题：

1. 今天需要完成哪些工作？
2. 每项工作为什么分配给我？
3. 完成它需要哪些输入和上下文？
4. 我的产出将流向谁、解锁什么步骤？
5. 这一步由我执行，还是可交给 Agent？

#### 首屏组件

- **今日待办：**待准备、待校验、待分析、待复核、待补件、待执行、待验证。
- **流程视图：**显示每项待办所属 Case、当前阶段、上游输入和下游责任人。
- **时间与风险：**截止时间、SLA、阻塞、依赖及升级状态。
- **工作上下文抽屉：**无需离开待办即可查看 Evidence、口径、评论、历史产出和模板。
- **执行方式：**每个适用任务显示“人工执行”“交给 Agent”“Agent 草拟、人工确认”三种模式；不可用模式解释原因。
- **团队视图：**财务经理可看到团队负载与阻塞，但第一版不制作复杂排班功能。

“财务执行人员”是原型体验分组，不是一个新的生产角色；具体权限仍来自 FP&A、Finance BP、财务经理或分析人员的角色及事项范围。

## 5. Decision Case Workspace

Case 页面不采用八个同权重页签，而采用“**阶段轨道 + 当前工作区 + 持久决策摘要**”。

### 5.1 页面框架

```text
Case 标题 / 状态 / Owner / 风险 / 截止日 / 模拟数据标识
触发 ─ 数据 ─ 分析 ─ 方案 ─ 审批 ─ 追踪 ─ 事后评价
┌─────────────────────────────┬──────────────────────────┐
│ 当前阶段主要工作区          │ 持久决策摘要             │
│ 数据、图表、方案或任务      │ 影响、推荐、风险、缺口   │
│                             │ 下一步、负责人、期限     │
└─────────────────────────────┴──────────────────────────┘
Evidence / Comments / Audit Timeline 抽屉
```

### 5.2 决策封面

包含事项名称和类型、触发原因、业务背景、影响范围、Owner/参与者/审批人、截止日期、当前建议、置信度、反方观点、关键风险、材料完整度及下一步。

### 5.3 数据（深入制作）

CFO 和执行人员看到同一数据版本，但默认粒度不同：

- 数据截至时间、期间、场景版本、币种、单位和“模拟”标识；
- Actual、Budget、上一版 Forecast、当前建议 Forecast；
- 按业务板块、基地和关键驱动下钻；
- 指标口径、来源类型、Evidence 快照和数据质量状态；
- 一条刻意设计的数据质量问题，以及修正前后的版本差异；
- 从图表数据点定位 Evidence，不要求第一版实现通用文件上传引擎。

### 5.4 分析（深入制作）

- 差异摘要和趋势；
- Bridge/Waterfall 驱动分解；
- 按 Volume、Mix、FX、HC、物流等驱动解释；
- 区分“已验证事实”“Agent 候选”“人工判断”“待验证假设”；
- 每条 Agent Insight 显示 Evidence 引用、方法、置信度、限制和复核状态；
- 人工可接受、修改、驳回，或把因果表述降级为假设并记录理由。

### 5.5 方案（深入制作）

至少并列四个方案：维持上一版、Agent 建议、FP&A 人工调整、压力情景。比较维度包括：

- Revenue、PTI、MVA 等财务影响；
- 经营驱动和资源影响；
- 与基线及上一版本差异；
- 关键假设与敏感性；
- 风险、反方观点、置信度；
- 时间影响、依赖和可逆性；
- 后续验证指标。

CFO 可从汇总比较进入具体方案及其 Evidence，但不能修改分析底稿；CFO 可要求补充、选择方案、附条件批准或驳回。

### 5.6 审批（由 CFO 操作）

审批确认页固定展示 Case、Evidence 和 Option 版本，CFO 可：

- 批准推荐方案；
- 选择其他方案并填写理由；
- 附条件批准；
- 驳回；
- 要求补充材料。

批准结果形成明确的执行边界和后续 Action。第一版只深入演示 CFO 这一审批动作；完整多级路由、金额阈值、代理和紧急审批仅在管理入口介绍。

### 5.7 追踪与事后评价

- 将 CFO 决定转换为 Action、Owner、里程碑、截止日和预期指标；
- CFO 看组合式进度、例外和需干预项；执行人员看具体待办与所需交付物；
- Verification 固定批准时的预期基线，展示实际值、偏差、归因、混杂因素和验证人；
- 事后评价回答“决定是否正确、执行是否到位、价值是否兑现、下次应复用或避免什么”；
- 形成一张经人工审核的 Decision Memory 示例卡，不深入制作知识管理功能。

## 6. 主演示路径：滚动预测决策闭环

第一版以合成的 `Server VN MVA Outlook` 为主演示事项。

| 步骤 | 角色与界面 | 演示内容 |
| --- | --- | --- |
| 1 | CFO / Cockpit | 发现 MVA Outlook 重大变化，但先不审批；进入 Case |
| 2 | FP&A / Workbench | 接收“验证数据”待办，查看 Actual/Forecast 和一条质量问题，修正后产生 Evidence 新版本 |
| 3 | Agent + FP&A / Case Analysis | Agent 生成驱动桥和候选洞察；FP&A 复核并将一条因果判断改为待验证假设 |
| 4 | FP&A / Case Options | Agent 生成方案，FP&A 修改 FX 假设并形成四方案比较，提交 CFO |
| 5 | CFO / Decision Workspace | 详细检查数据、分析、假设、反方观点和四方案；附条件批准人工调整方案 |
| 6 | 执行人员 / Workbench | 系统生成发布与跟踪待办，展示人工、Agent 草拟人工确认、Agent 模拟执行三种方式 |
| 7 | Agent / Workbench | 在演示授权内执行“模拟发布”；用户可停止或接管；返回 MOCK 回执 |
| 8 | CFO + FP&A / Tracking | 查看执行进展和一次例外，Owner 更新处理结果 |
| 9 | FP&A / Verification | 新合成 Actual 到达，对比批准基线，记录预测准确性、归因和混杂因素 |
| 10 | CFO / Evaluation | 查看事后评价和经验卡，关闭 Case |

### 6.1 必须演示的例外

仅深入制作四个与目标直接相关的例外：

1. 数据质量错误阻止分析定稿；
2. Agent 低置信度或错误因果表述被人工修正；
3. CFO 要求补件或作附条件批准；
4. Agent 执行被停止并切换为人工接管。

其他越权、代理、授权过期、知识过期等例外保留在介绍页，不要求第一版可操作。

## 7. 财务执行人员的“一个工作日”演示

除跟随主 Case 外，Finance Workbench 还展示一个合成工作日，证明它不是单一流程页面：

| 待办 | 来源 | 所需工作 | 执行方式示例 | 产出去向 |
| --- | --- | --- | --- | --- |
| 校验 Forecast Evidence | 滚动预测 Case | 检查口径与异常 | 人工确认，Agent 预检 | 解锁分析任务 |
| 复核驱动洞察 | 绩效回顾 Case | 验证 Evidence 和因果措辞 | Agent 草拟、人工确认 | 提交经理/CFO |
| 补充 Capex 假设 | 资源申请 Case | 补充利用率与现金影响 | 人工执行 | 重新进入方案比较 |
| 发布已批准预测 | 滚动预测 Case | 执行授权内发布 | 人工或 Agent 模拟 | 生成回执和跟踪任务 |
| 验证行动价值 | 绩效回顾 Case | 对比预期与实际 | Agent 计算、人工归因 | 事后评价 |

每项待办必须显示分配原因、输入、期望产出、截止时间、下游责任人及可选执行模式，以体现从“找材料和催进度”转向“由工作流提供上下文和交付标准”。

## 8. 人工向 Agent 切换的交互

第一版不宣称 Agent 已能替代岗位，而是展示**任务级切换**。Agent 分析、建议、运行过程、工具调用和回执全部使用可控模拟，不调用真实模型或真实执行工具：

1. 每个任务模板声明是否适合 Agent，以及允许的模式；
2. 用户选择 Agent 时先查看拟使用输入、输出、工具、授权范围和停止条件；
3. Agent 可准备草稿、完成预检，或在批准后执行一个模拟动作；
4. 运行中显示状态、步骤和停止入口；
5. 低置信度、超范围、输入缺失或工具失败时转人工；
6. 人工接管继承全部上下文，并明确哪些步骤已由 Agent 完成；
7. 所有 Agent 输出、人工修改和最终责任人进入 Case 时间线。

切换单位是“任务步骤”而不是整个职位，也不是整个 Decision Case。

## 9. 其他模块的入口页标准

每个 L1 入口页只需统一展示：

- 模块解决的问题；
- 目标用户；
- 主要对象及输入输出；
- 与 Decision Case 的关系；
- 未来生产能力；
- 第一版未实现的范围；
- 一个进入主 Case 示例的链接（适用时）。

这保证产品版图完整，同时不会把静态概念页误解为已实现功能。

## 10. 合成演示数据

第一版数据集应小而连贯，建议包括：

- 一个主演示 Forecast Case；
- Actual、Budget、上一版 Forecast 和当前建议四个视图；
- 四个 Evidence 版本，其中一个含数据质量问题；
- 六至八条 Insight，覆盖事实、Agent 候选、人工判断和待验证假设；
- 四个 Options；
- 一次 CFO 附条件批准；
- 三个 Actions 和一条执行例外；
- 一次停止后人工接管的 Agent Run；
- 一个 Verification 和一张 Decision Memory 卡；
- Finance Workbench 中来自三类 Case 的五条待办。

示例使用虚构周期、虚构用户及合成数值，不复用现状报告中的实际金额。每个数据视图和导出均保留模拟水印。

## 11. 可运行 Web 原型边界

### 11.1 必须真实工作的原型能力

- 页面路由、导航、返回路径和深链接；
- CFO 与 FP&A Analyst 两个演示身份的切换及差异化首页；
- 主 Case 在数据、分析、方案、审批、追踪和事后评价之间的状态流转；
- 待办完成、补件、审批、Agent 停止和人工接管等关键交互；
- 本地模拟数据驱动的图表、方案比较和界面状态；
- 当前演示会话内的状态保持，避免刷新前后无故矛盾；
- 清晰的加载、空、成功、失败、禁用及恢复反馈。

### 11.2 必须模拟的能力

- 企业身份认证与真实权限目录；
- 数据湖、实时数仓、SAP、OA、APEC、智慧财务及通知系统连接；
- 模型推理、Agent 规划和工具执行；
- 真实预测发布、预算写回、任务外发或审批同步；
- 生产审计、加密、密钥、备份、灾备和性能能力。

模拟不能只表现为静态文案：关键 Agent Run 应有可预测的阶段、耗时、停止点、失败点和模拟回执，使用户可以评审人机协作交互，但不得暗示背后存在真实模型或企业连接。

## 12. 视觉与响应范围

### 12.1 设计基调

参照用户提供的界面附件，采用**蓝—白主基调、低饱和度、专业、克制、数据密集的企业财务工作台**风格：

- 深蓝色左侧主导航建立稳定的 Workspace 框架；
- 主内容区采用白色和极浅冷灰/浅蓝背景；
- 品牌蓝用于主操作、选中状态、关键趋势和可交互链接；
- 青绿色用于正向或正常状态，橙色用于提醒，红色仅用于高风险、负向偏差和阻断；
- 卡片使用轻边框、低强度阴影和中等圆角，不使用高饱和渐变或强装饰；
- 图表优先使用蓝色系区分 Actual、Forecast、Budget 和置信区间，并辅以线型、标签和图例，不能只依赖颜色；
- 数字、金额、期间和状态建立清晰层级，适合 CFO 快速扫描，也支持 Analyst 阅读高密度明细；
- Agent 使用统一的蓝紫或青蓝辅助标识，但不得在视觉层级上压过决策、风险和待办。

### 12.2 布局基准

- 以 PC 屏幕 **1920×1080** 为主要演示分辨率；
- 内容设计基准宽度为 1920px 视口，确保浏览器常规缩放下首屏信息完整；
- 采用固定或可收起的左侧导航、顶部全局工具栏及自适应主内容区；
- CFO Cockpit 可采用“主分析区 + 右侧待决策/Agent 状态栏”的宽屏布局；
- Finance Workbench 优先保证待办队列与任务上下文能够并排阅读；
- 第一版不设计移动端导航、触控手势、移动审批或小屏重排；较窄桌面只需提供合理的最小宽度和水平布局保护，不承诺响应式移动体验。

### 12.3 组件表达

- 顶部栏显示产品名、演示期间、范围、当前角色和模拟环境标识；
- KPI 卡只承载与决策有关的指标，并显示单位、比较基线和趋势；
- 待决策/待办卡显示编号、风险、影响、Owner、截止时间和明确下一步；
- 主次按钮区分“查看/准备”“提交/审批”“模拟执行”等不同后果，高风险动作二次确认；
- Agent Insight 卡显示生成者、依据、置信度、限制和人工复核状态；
- 所有页面保持足够对比度、可见焦点和文本状态，低饱和不等于低可读性。

## 13. 原型评审与完成标准

### 13.1 CFO 走查

- 能否从 Cockpit 找到需要决定的事项；
- 是否看清数据来源、版本、分析逻辑、方案差异和主要风险；
- 是否理解自己批准的具体方案及条件；
- 是否能在审批后继续观察执行与价值；
- 是否愿意用该 Case 代替分散的报告、邮件和会议追踪。

### 13.2 FP&A Analyst 走查

- 是否能从待办理解今天要做什么及为什么；
- 是否无需跨多个系统手工拼接上下文；
- 是否明确每一步的输入、交付标准和下游；
- 是否理解人工、Agent 草拟及 Agent 执行的差异；
- Agent 停止后是否能顺利人工接管。

### 13.3 通过条件

- 两类用户能明确描述彼此不同的首页和职责；
- CFO 完成一次数据—分析—方案—审批—追踪—评价闭环；
- 财务执行人员完成至少三类待办；
- 人工/Agent 两种执行方式均完成一次演示；
- 其他主要模块入口均可访问且范围标识准确；
- 无页面、数据或回执被误认为生产能力或真实企业数据。
