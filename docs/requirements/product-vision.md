# FIN Workspace 产品愿景

## 1. 产品定义

FIN Workspace 是面向企业财务组织的**财务决策操作系统**，不是新的交易系统、传统财务门户或报表目录。它以 **Decision Case（决策事项）**为业务主线，将“数据 → 洞察 → 决策 → 授权 → 执行 → 监督 → 验证 → 组织记忆”串成一个有责任人、有证据、有控制且可审计的闭环。

其价值不在替代 SAP、数据湖、APEC、智慧财务、OA 或 Office 365，而在这些系统之上形成跨系统的决策与执行控制面。

## 2. 背景与机会

现状材料表明，财务工作已经具备月度复盘、滚动展望、差异桥、行动跟踪等实践，但信息分散于长篇材料、报表、流程和人工协作；同一轮复盘同时承担回顾、预测及行动跟踪。FIN Workspace 应把既有业务语境（PCBG、Server、IDSG，HF/VN，Actual/Budget/Target/Forecast 等）带入统一工作流，而不是另建脱离现状的指标体系。

> **事实边界：**现状文档未完整描述角色权限、系统接口、痛点量化及数据表结构；本文对这些部分的补全均是待验证的“设计假设”，不作为公司现状事实。

## 3. 目标用户

| 用户 | 首要目标 | Workspace 提供的价值 |
| --- | --- | --- |
| CFO / 财务领导 | 聚焦重大事项、配置资源、授权并监督价值 | 决策队列、方案比较、风险与价值组合视图 |
| FP&A / 绩效管理 | 更新预测、解释偏差、准备管理决策 | 证据到洞察的可复用分析及预测工作流 |
| Finance BP | 支持经营决策、申请资源、推动行动 | 结构化申请、方案影响和跨团队行动闭环 |
| 财务经理 | 分工、复核、审批与例外升级 | 工作队列、质量门、SLA 与升级机制 |
| 财务分析人员 | 准备数据、验证证据、维护模型与知识 | 数据接入、血缘、分析草稿和知识复用 |

交易处理人员不是 MVP 主要用户；其数据、控制结果、交付状态及 SLA 异常可作为未来输入。

## 4. 价值主张

1. **提高决策速度：**以事项而非文件组织上下文，减少反复寻找数据和拼装材料。
2. **提高决策质量：**并列呈现证据、假设、选项、反方观点、置信度与风险。
3. **把审批变成可执行授权：**审批明确范围、金额、期限、条件及获准工具，不等同于笼统同意。
4. **实现价值闭环：**从建议一路追踪到行动结果，并比较预期价值与实际价值。
5. **形成组织记忆：**保留当时可用证据、判断、版本与结果，支持后续检索和复盘。
6. **安全采用 Agent：**近期限定于 L1 建议与 L2 经批准执行，所有行为可解释、可停止、可审计。

## 5. 产品原则

- **Decision Case 优先：**看板、报表、审批、任务与知识均可进入或回到相关事项。
- **证据优先于叙事：**结论必须能追溯至来源、快照、处理步骤和责任人。
- **人在关键控制点负责：**Agent 不做最终因果判断、方案权衡、授权或例外处置。
- **授权最小化：**授权限定主体、动作、对象、额度、期限及撤销条件。
- **建议与事实分离：**事实、人工判断、模型生成内容、设计假设均有清晰标签。
- **默认可审计：**关键对象采用版本化、追加式事件记录；不以覆盖历史代替更正。
- **异常可见：**低置信度、缺失证据、职责冲突、超阈值与 SLA 违约优先暴露。
- **渐进集成：**原型以显著标记的模拟数据验证体验，生产连接器另行安全评审。
- **复用统一机制：**三条核心流程共享事项、证据、审批、行动、验证和审计能力。

## 6. MVP 原型范围

第一版原型只深入验证三个目标：

1. 展示 Workspace 的主要界面和整体产品版图，并明确区分 CFO 的决策界面与财务执行人员的工作界面。
2. 为 CFO 深入演示一个以决策为核心的闭环：数据 → 分析 → 方案 → CFO 审批 → 追踪 → 事后评价。其中数据、分析和方案比较必须达到可评审深度。
3. 为财务执行人员深入演示以待办事项和工作流整合日常工作的方式，并体现同一个执行步骤如何在受控条件下由人工执行切换为 Agent 执行。

深做范围限于 CFO Cockpit、Finance Workbench / My Work、Decision Case 决策工作台，以及支撑主演示路径所需的数据、分析、方案、审批、追踪和事后评价界面。其他业务域、知识、管理、完整数据中心和 Agent 管理中心只保留可导航的界面入口、用途介绍和未来能力说明，不实现深入功能。

## 7. 非范围

### 7.1 MVP 明确不做

- 连接真实数据湖、SAP、OA 或其他企业系统。
- 使用真实企业凭据、个人数据、敏感经营数据或真实审批。
- 自动过账、付款、采购、招聘、预算写回等真实执行。
- 无人值守自治、未经授权的工具调用或最终决策。
- 构建完整 ERP、BI 平台、主数据治理平台或通用流程引擎。
- 以原型的云端运行方式承诺生产部署形态、性能或安全认证。

### 7.2 未来生产能力

受控企业环境/内部部署、企业身份与组织同步、真实连接器、细粒度数据权限、密钥管理、灾备与可观测性、模型治理、数据驻留、合规归档及经批准的执行工具属于未来生产设计。

## 8. 成功衡量（设计假设）

MVP 以体验验证而非经营结果承诺为目标：三个场景均可从触发走到验证；任一建议可在三次以内交互定位依据；高风险动作未经合格审批不能进入模拟执行；任一关键事件可按操作者、时间、对象版本还原。
