# 核心工作流

> **第一版原型深度：**本文件保留三条流程的完整目标设计，作为产品需求和后续演进依据；第一版交互原型采用“一深两浅”，只完整制作一条 CFO 决策闭环，另外两条仅用入口和代表性页面验证统一机制。详见 `docs/architecture/prototype-specification.md`。

## 1. 统一闭环与状态

三个场景共用 Decision Case 主状态：`草稿 → 分析中 → 待复核 → 待审批 → 已授权 → 执行中 → 待验证 → 已关闭`。旁路状态为`需补件`、`已驳回`、`已撤回`、`已暂停`、`已取消`。状态变化由权限、必填质量门和审计事件约束，而非任意修改。

通用控制点：

1. 触发与分级：记录来源、业务背景、影响范围、负责人、截止日、金额与风险等级。
2. 证据与分析：固定数据快照和口径；区分事实、假设、人工判断及 Agent 生成内容。
3. 方案与建议：至少保留“维持现状/不行动”基准（不适用时说明原因），量化影响、风险和置信度。
4. 复核与授权：先内容复核，再按阈值和职责分离路由审批；授权包含范围、额度、期限、条件和撤销规则。
5. 执行与监督：将授权转换为 Action；真实系统写操作在 MVP 中仅模拟。
6. 验证与记忆：比较预期/实际价值，说明归因与局限，经人工确认后形成可检索知识。

## 2. 场景一：滚动预测更新

### 2.1 正常流程

| 步骤 | 人 | Agent | 系统与产物 |
| --- | --- | --- | --- |
| 1. 触发 | FP&A 确认预测周期和范围 | 检查新实际/业务驱动模拟数据 | 新建 Forecast Case，冻结基线 Evidence |
| 2. 校验 | 分析人员解决映射与口径问题 | 执行完整性、异常值与版本检查 | 校验报告、血缘、异常列表 |
| 3. 分析 | FP&A 判断业务因果 | 生成 Actual vs Forecast/Budget/CtC 差异和驱动候选 | Insight、驱动桥、置信度及限制 |
| 4. 建议 | FP&A/BP 提供业务判断并可覆盖 | 提出预测值、情景和敏感性 | 基线/建议/压力等 Option |
| 5. 人工调整 | FP&A 修改预测并填写理由 | 重算影响并提示不一致 | 新预测版本、覆盖记录 |
| 6. 复核审批 | 经理复核；授权人批准/驳回 | 仅检查质量门和阈值 | Approval、批准快照、发布授权 |
| 7. 发布 | 获授权人员确认发布 | 在明确授权下执行“模拟发布” | 发布回执、不可变版本、审计事件 |
| 8. 验证 | FP&A 审阅实际结果和归因 | 计算偏差、偏差趋势和建议校准 | Verification、准确性指标、复盘知识 |

### 2.2 例外流程

- 数据缺失/口径冲突：标记 Case `需补件`；禁止提交审批，除非授权人接受显式数据例外。
- Agent 低置信度或驱动不稳定：不自动推荐，转人工分析并展示原因。
- 人工覆盖重大：要求覆盖理由；超阈值触发额外复核。
- 审批后驱动发生重大变化：使未使用授权失效，创建新版本并重新审批。
- 模拟发布失败：不静默重试；进入暂停状态，由人决定重试、回退或取消。

## 3. 场景二：资源申请与调整

### 3.1 正常流程

| 步骤 | 人 | Agent | 系统与产物 |
| --- | --- | --- | --- |
| 1. 发起 | BP/申请人选择 OPEX、HC 或 Capex，填写目的、期限和责任中心 | 引导缺失字段 | Resource Case 与申请基线 |
| 2. 取证 | 分析人员验证预算余额、业务量和历史使用（均为模拟） | 汇总证据、标记新鲜度 | Evidence、数据质量状态 |
| 3. 比较方案 | BP/FP&A 确认“不批/部分/全额/延后”等 | 计算损益、现金、产能、HC、风险和敏感性 | Option 及影响矩阵 |
| 4. 推荐复核 | 经理挑战假设与反方观点 | 生成建议和置信度，不作最终选择 | Insight、推荐草案、风险 |
| 5. 分级审批 | 不同授权人按金额/风险/资源类型依次或并行审批 | 只校验路由和职责冲突 | 条件化 Approval 与授权包 |
| 6. 通知执行 | 申请人确认接受条件；执行人接收任务 | 经批准后发送模拟通知/生成模拟执行任务 | Action、回执、预算保留模拟记录 |
| 7. 使用监督 | BP/经理更新里程碑，处理例外 | 监控使用率、SLA、超支和闲置 | 例外、升级与状态 |
| 8. 价值验证 | 财务与业务共同确认收益/成本 | 对比承诺与实际，提出归因候选 | Verification 与复盘 |

### 3.2 例外流程

- 超预算、超金额或高风险：提升审批级别；不得拆单绕过阈值。
- 申请人与审批人/执行人职责冲突：阻止审批并重新路由。
- 审批代理：仅在有效期、事项范围和额度内；原审批人及审计员可见。
- 部分批准/附条件批准：系统生成新授权边界，申请人接受后才执行。
- 额度到期、范围改变或重大假设变化：暂停未执行任务并重新审批。
- 使用率或价值偏离：形成子 Case 或例外 Action，必要时冻结剩余额度。

## 4. 场景三：绩效回顾与行动管理

### 4.1 正常流程

| 步骤 | 人 | Agent | 系统与产物 |
| --- | --- | --- | --- |
| 1. 触发 | FP&A 选择期间、版本和业务范围 | 扫描 Actual vs Target/Budget/Forecast 异常 | Performance Case 与差异 Evidence |
| 2. 分析 | 分析人员验证数据；BP 判断原因 | 生成趋势、分层拆解、Bridge 和驱动候选 | Insight、证据引用、置信度 |
| 3. 会前准备 | 经理决定议题和参会人 | 起草 Highlight/Lowlight、问题与建议 | 决策简报草稿 |
| 4. 管理讨论 | 领导进行因果判断、权衡和决策 | 记录结构化纪要草稿，不代替决策 | Option、决策、反方意见与审批 |
| 5. 行动分派 | 经理确认负责人、期限、价值指标和依赖 | 提议拆解与提醒 | Action、里程碑、SLA |
| 6. 监督 | Owner 更新进度和证据；经理处理例外 | 提醒、识别阻塞和预测逾期 | 进展、例外、升级 |
| 7. 验证 | 财务验证数值；业务确认可持续性 | 比较预期/实际并提示混杂因素 | Verification、价值差异 |
| 8. 复盘 | 责任人确认可复用结论 | 生成知识草稿 | 经审核的 Decision Memory |

### 4.2 例外流程

- 指标异常被证明为数据问题：保留原触发，标记“数据质量原因”，创建修复 Action。
- 管理讨论无结论：Case 保持分析中，记录分歧、补充证据负责人及下次决策期限。
- 行动跨 Case 重复：允许一个 Action 关联多个 Case，但指定主 Case，防止重复计值。
- 行动逾期/阻塞：先提醒，达到 SLA 后升级；Agent 不能自行更换负责人或期限。
- 价值不可验证：记录原因、替代指标和验证窗口，不得虚构实际价值。

## 5. 人与 Agent 责任矩阵

| 活动 | Agent | 人类 | 强制控制 |
| --- | --- | --- | --- |
| 数据整理/异常扫描 | 准备、检测、解释草案 | 验证口径与适用性 | 来源、快照、运行记录 |
| 因果判断 | 提出候选与反证 | **最终负责** | 不把相关性呈现为已证实因果 |
| 方案与影响 | 生成备选和敏感性 | 挑战、修改、权衡 | 假设与不确定性可见 |
| 推荐 | 可建议（L1） | **决定是否采纳** | 置信度、限制、反方观点 |
| 授权 | 不得授权 | **合格审批人授权** | 阈值、职责分离、有效期 |
| 执行 | 仅按批准范围执行（L2） | 可启动、停止、处理例外 | 工具白名单、幂等、熔断、回执 |
| 验证 | 计算和归因候选 | 确认结果与责任 | 预期基线不可事后覆盖 |
