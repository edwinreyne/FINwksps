# MVP 需求与验收标准

## 1. 需求级别

- **MUST：**原型评审必须具备。
- **SHOULD：**若不影响闭环则可降级，但需说明。
- 所有展示数据均须为虚构/合成数据，并持续显示“模拟数据 / 非真实企业数据”。

## 2. 功能需求

| ID | 级别 | 需求 | 可测试验收标准 |
| --- | --- | --- | --- |
| FR-01 | MUST | 创建并维护统一 Decision Case | 可创建三类 Case；必含背景、范围、责任人、期限、证据、假设、洞察、选项、推荐、风险、授权、审批、行动、验证和审计区域；缺关键字段不能提交 |
| FR-02 | MUST | 状态机与版本 | 仅允许定义的状态迁移；每次提交/批准固化版本；历史版本可比较且不能被覆盖 |
| FR-03 | MUST | 证据与血缘 | 每项 Evidence 显示来源类型、模拟标记、数据期间、版本、上传者/运行、时间、质量状态及变换说明；Insight 能反向定位 Evidence |
| FR-04 | MUST | 模拟数据呈现 | 主演示 Case 可详细查看合成数据、指标口径、期间、版本、来源、质量状态和 Evidence 血缘；第一版无需实现通用上传处理流程 |
| FR-05 | MUST | 分析与洞察 | 可展示差异、趋势、驱动桥和风险；每条 Insight 标注人工/Agent、依据、置信度、限制与复核状态 |
| FR-06 | MUST | 方案比较 | 同屏比较至少两个方案及基准方案的财务、经营、现金、风险、时间与敏感性；无法量化项明确标注 |
| FR-07 | MUST | Agent 建议治理 | Agent 输出显示运行 ID、目的、输入引用、模型/提示配置版本、置信度和限制；人可接受、修改、拒绝并记录理由 |
| FR-08 | MUST | CFO 审批 | CFO 可在详细查看数据、分析、方案、假设和反方观点后亲自批准、驳回或要求补充；决定引用固定版本并留痕 |
| FR-09 | SHOULD | 控制说明 | 主路径展示审批人与准备人职责分离；完整阈值、代理和多级审批配置只保留说明入口 |
| FR-10 | MUST | 人工/Agent 执行切换 | 同一任务模板可选择“人工执行”或“Agent 执行”；界面明确能力、授权、输入、输出、停止和接管条件；Agent 路径仅产生模拟回执 |
| FR-11 | MUST | 行动管理 | Approval 可生成含 Owner、期限、依赖、状态、价值指标的 Action；逾期和阻塞可见并按规则升级 |
| FR-12 | MUST | 验证与价值 | Verification 固定预期基线，记录实际值、差异、归因、验证期、证据及确认人；无法验证时必须说明原因 |
| FR-13 | MUST | 双角色前端 | CFO Cockpit 聚焦决策、风险、进展和价值；Finance Workbench 聚焦今日待办、流程步骤、输入、产出、阻塞和 SLA；两者进入同一 Case 时呈现符合职责的视图 |
| FR-14 | SHOULD | 入口与介绍页 | Resource Allocation、Knowledge、Administration、Data Center 和 Agent Center 等非核心模块可进入，显示用途、未来能力和“本原型未深入实现”标识 |
| FR-15 | MUST | 决策时间线 | 主演示 Case 的数据版本、分析、方案修改、CFO 决定、执行更新和事后评价形成可查看时间线 |
| FR-16 | SHOULD | 权限说明 | 主路径实际区分 CFO 与财务执行人员；完整查看、编辑、提交、复核、审批、执行、监督、配置矩阵保留设计说明，不要求全部交互实现 |
| FR-17 | MUST | 一深两浅场景 | 选择一条 CFO 决策闭环作为深入演示；另外两条场景以入口、代表性页面和流程说明证明可复用性，无需完整可操作闭环 |
| FR-18 | MUST | 财务工作队列 | 财务执行人员可按待办、工作流、截止时间、阻塞和执行方式组织日常工作，并从待办进入所需上下文而无需自行拼接材料 |
| FR-19 | SHOULD | 决策简报 | 从主 Case 展示可审核的管理摘要，明确时点、版本、模拟标识和 Evidence 引用 |

## 3. 非功能需求

| ID | 领域 | 要求与验收 |
| --- | --- | --- |
| NFR-01 | 安全 | 默认拒绝；演示账号不得包含真实身份；敏感字段遮罩体验可演示；越权测试均被拒绝并留痕 |
| NFR-02 | 审计完整性 | 关键事件具操作者/Agent、UTC 时间、对象/版本、动作、理由和关联 ID；界面无直接删除审计记录能力 |
| NFR-03 | 可解释性 | 任一 Agent 建议可定位输入证据、处理目的、假设、置信度与限制；不要求暴露模型内部思维链 |
| NFR-04 | 可停止性 | 活跃 Agent Run 有可见状态和停止入口；停止后不再启动新工具调用，已产生结果标记为不完整 |
| NFR-05 | 可用性 | 以 1920×1080 PC 桌面为主演示环境；关键路径具一致导航、空/错/加载状态；高风险批准需二次确认；不能只靠颜色传递状态；第一版不要求移动端体验 |
| NFR-06 | 性能（原型目标） | 本地模拟数据下，主要列表/详情交互目标 2 秒内可用；Agent 模拟长任务显示进度，不以此承诺生产 SLA |
| NFR-07 | 数据隔离 | 原型数据与未来生产配置逻辑隔离；所有样例页面及导出均带模拟水印 |
| NFR-08 | 可移植性 | 原型为可运行 Web 应用，但不把单一模型或连接器写死在领域对象；接口契约可替换；生产部署另行验证 |
| NFR-09 | 可靠性 | 模拟执行支持幂等键、失败状态与人工重试；重复请求不会产生两条成功执行记录 |
| NFR-10 | 可访问性 | 键盘可达、焦点可见、状态有文本、表格有标题；原型评审执行基础无障碍检查 |
| NFR-11 | 隐私与保留 | 原型仅合成数据；生产前必须定义分类、最小化、保留、合法导出和删除/封存政策 |

## 4. 明确不做

不接真实系统、不写回真实业务、不使用真实凭据或敏感数据、不实现自主审批/自治执行、不替代 ERP/BI/OA、不训练企业专属模型、不承诺生产级容量/高可用/合规认证、不实现移动端完整体验。

## 5. MVP 总体验收场景

1. **产品版图：**评审者可浏览所有主要模块入口，并能明确说出 CFO 界面、财务执行界面及各非核心入口的用途。
2. **CFO 闭环：**CFO 从 Cockpit 进入一个重大 Decision Case，详细检查数据、分析与至少三个方案，亲自审批，并继续查看执行追踪和事后评价。
3. **执行工作台：**财务执行人员从 My Work 完成至少三个不同类型的待办，系统为每一步提供输入、上下文、产出、截止时间和后续流向。
4. **人工/Agent 切换：**同一执行任务分别演示人工模式和 Agent 模式；Agent 模式说明授权边界、可停止和人工接管，且不产生真实系统动作。
5. **可追溯：**从 CFO 建议进入数据快照，并返回批准版本；审批后可关联到 Action、进展和 Verification。
6. **范围诚实：**非核心入口明确标记为概念介绍；任一页面、数据、导出或回执均不会被误认为生产能力或真实经营信息。

## 6. 退出条件

- 所有 MUST 验收通过；SHOULD 的偏差已记录。
- 一个 CFO 决策闭环和一个财务执行人员工作日路径完成角色走查。
- 另外两个业务场景完成入口与复用概念走查，不要求完整操作。
- 未决的阈值、部署、保留和系统接口不被原型默认值包装为已确认政策。
