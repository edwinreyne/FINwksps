# Project instructions

## Required reading

Before planning or implementing substantial changes:

- Read `docs/requirements/` for authoritative requirements.
- Read relevant files in `docs/architecture/`.
- Consult `docs/reference/` for supporting materials.

## Working rules

- Treat `docs/requirements/` as the authoritative business requirements.
- Explain any conflict between implementation and reference documents.
- Keep documentation updated when important decisions change.
- Ask for clarification when requirements are ambiguous.
